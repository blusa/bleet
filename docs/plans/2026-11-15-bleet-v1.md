## Global constraints

- Work in this repository on `feat/bleet-ios-testflight`; existing design changes are ours and included. No unrelated files or existing release identities changed.
- Backend and app are separate independent ownership domains. Backend owner edits `backend/**`; iOS owner edits `ios/**`. Root owns shared contracts, integration, deployment, signing, ASC, CI, PR and merge.
- Secrets remain outside git/artifacts/logs. API and MCP are authenticated. Bind backend only on ZORAK loopback; Caddy enforces tailnet/loopback origins and uses the existing valid wildcard TLS/DNS configuration.
- First version is functional with real collector data. Demo/offline exploration is explicitly labeled. Unsupported GPU and missing data are not zero. Widgets use timestamped App Group snapshots.
- App IDs: `cloud.blusa.bleet`, widget `cloud.blusa.bleet.widgets`, App Group `group.cloud.blusa.bleet`. Apple team `VMGQ6AAMB5`. Version `0.1.0`, build starts at `1` and increments for each upload.
- App default server is the requested custom HTTPS origin. Enroll with one-time code and store resulting device token in Keychain; do not embed tokens in the application.
- Scope is TestFlight beta distribution, not a public App Store release.

| 2 + 4 | Bundle IDs, App Group, project/signing | IDs fixed above; root performs publishing; native owner builds only |

| 3 | Earlier Serve proposal vs latest user command | Caddy only, private hostname, no Serve |
| 4 + 5 | Full-send deployment and merge | User explicitly authorizes TestFlight invitation and full-send merge after proof |

Ruling: use a feature branch in the current shared checkout rather than creating another worktree; the user requested this repository, all current edits belong to this task, and full-send delegates routine reversible workspace choices. This avoids losing the uncommitted design baseline and gives workers disjoint ownership.
